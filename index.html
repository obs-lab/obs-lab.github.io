What OBS-LAB does

Data processing and analysis

Charts, statistical analysis, forecasting and Monte Carlo simulation, computed locally. A robust-statistics stack recovers reliable estimates when a handful of anomalous observations would distort ordinary methods.

Semantic document search

Ask questions in natural language, in any language, and get answers that cite the documents they come from. Dense retrieval with cross-encoder reranking, and every report checked citation by citation.

Code and formulas

Run scripts against your archive in Python, R, Octave, JavaScript, Java, C and C++, each in a disposable sandboxed container with no access to the host. HTML and CSS preview live in the browser.

Clustering and entity analysis

Group related material into themes across the whole archive and explore an entity graph that resolves people, organisations and places and links entities that appear together.

Modules

Worksheets and plotting for tabular data, computed entirely on the local machine. Type data straight into spreadsheet-style grids, no document upload needed. Column roles (X, Y, error bars, labels, groups) drive every plot, so an error column set once is reused by every chart that accepts it. This panel is fully isolated: its data lives in a separate database and never touches the document archive, the search index or the entity graph.

  • 32 chart types, from interactive 3D surfaces and contour maps to Piper, ternary, wind-rose and violin diagrams
  • Curve fitting on nine nonlinear models, regression and peak analysis
  • Descriptive statistics, hypothesis tests, correlation matrices
  • Holt-Winters forecasting and Monte Carlo simulation
  • Robust regression for contaminated samples
  • Signal processing on the worksheet columns

Ingestion handles chunking and embeddings; retrieval runs on a FAISS index with cross-encoder reranking.

  • Natural language questions in any language
  • Answers with citations verified against the source chunks
  • Clustering of the archive into themes
  • Entity graph with typed, source-verified relations
  • Audit trail of every query

Scripts execute in disposable containers, with an ephemeral permission-scoped token as the only route to the database.

  • Python, R, Octave, JavaScript, Java, C, C++
  • Configurable timeout and memory ceiling per run
  • Plots returned to the interface and stored in the archive
  • HTML and CSS previewed live in the browser

Images are indexed by visual content and by the text they contain.

  • Search by phrase, for example "red car near a building"
  • OCR indexing of text inside images
  • Colour sampling and comparison
  • Chart digitiser: recover numeric series from a chart image
  • Visual and textual clustering

Privacy by design

The design principle is that your archive never leaves your infrastructure. Models run on your hardware and data is stored locally. The only outbound traffic possible is a cloud language model that you must explicitly enable. Search, statistics, clustering and image analysis never depend on that choice.

A thin desktop shell built on Tauri loads a web interface served by a local FastAPI backend. For the language model you choose one of three modes:

Local, fully offline

The language model runs on your own hardware. No request ever leaves the machine, even for generated reports.

No outbound traffic

No model at all

Skip generation entirely. Search, statistics, clustering and image analysis keep working without any language model.

No outbound traffic

Cloud API

Opt in to an external provider only when you choose to. This is the single route by which any data can leave your infrastructure.

Outbound, opt-in

Search, statistics, clustering and image analysis never depend on that choice.

On-premise deployment

OBS-LAB is a B2B product. Each customer is set up on site: the platform is installed and configured directly on your own servers, so the whole archive and every model stay within your infrastructure. Because the deployment runs from the source, it is not tied to a single operating system and can be fitted to the environment your organisation already runs.

Setup, configuration and any adjustments are handled together with the developer behind OBS-LAB, so the installation matches how your organisation actually works. To start, use the client request form below.

Frequently asked questions

Does my data ever leave my servers?

No, unless you deliberately enable the cloud language model. In local or no-model mode there is no outbound traffic at all. Ingestion, search, statistics, clustering and image analysis all run on your hardware.

How is OBS-LAB installed?

Installation is done on site, on your own infrastructure, as part of the deployment agreed with you. Because it runs from the source, it is not limited to a single operating system.

Is running code against my archive safe?

Scripts run in disposable, sandboxed containers with no access to the host. The only route to data is an ephemeral, permission-scoped token, and each run has a configurable timeout and memory ceiling.

Can several people use the same instance?

Yes. Each person signs in and sees only their own material, with role-based ownership and sharing across groups.

Which languages can I run?

Python, R, Octave, JavaScript, Java, C and C++, each in its own container. HTML and CSS preview live in the browser.

Are the worksheets connected to my documents?

No. The worksheet panel keeps its data in a separate database that never touches the document archive, the search index or the entity graph.

Recover numbers from a chart image

The same module indexes images by visual content and by the text inside them, samples and compares colours, and clusters a picture collection visually or textually.
